# SOC Log Lab

SOC Log Lab creates compact synthetic log exercises for analysts and educators. It runs entirely in a modern browser and provides explicit controls for log family, total rows, baseline positive detections, difficulty (1–5), and a private trainer seed. Download the analyst JSONL and answer-key JSON separately; the Linux families also offer raw syslog text.

## Try it

Open `index.html` from a local static web server or visit the published RandomVibez path when available. The generator makes no network requests, does not use browser storage, and does not need an account or backend.

## Output and safety boundaries

- Difficulty preview rule: `min(total rows, base positive detections + difficulty - 1)`. Higher levels add one planted finding per tier above 1, then allocate correlated supporting records when space allows and reduce the explicitness of some cues.
- A cryptographically random private trainer seed is generated by default. Keep it private; it is included only in the separate answer key, not in analyst JSONL or raw syslog. If Web Crypto secure randomness is unavailable, generation fails closed; there is no `Math.random` fallback.
- The same app version + settings + seed reproduces scenario content and ordering. Record IDs and numeric process IDs are independently generated with Web Crypto for each dataset, so they differ between generations and do not reveal the pre-shuffle finding allocation. For exact replay, retain the paired analyst log and answer-key files together.
- Linux options produce RFC 5424-shaped synthetic raw syslog and JSONL. Each record includes a training row ID to cross-reference the answer key; the raw RFC-style message carries that ID in its message text. They are examples, not a claim of exact distro-specific defaults.
- Sentinel-shaped rows use documented Syslog table field names; CrowdStrike-shaped rows use selected CPS/ECS-inspired fields; Rapid7 output resembles generic-syslog search records. All vendor-shaped rows are explicitly training-only and are not official exports, ingest-ready formats, or schema-validated vendor payloads.
- Hosts use `.example.test` and source IPs use TEST-NET documentation ranges. There are no real credentials, malware, or actual indicators of compromise. These rows must not be treated as threat intelligence or used to validate production detections without review.
- Export files are unencrypted. The app does not persist its inputs or generated dataset. The RandomVibez site’s existing cookie notice is included; its privacy behavior is described on the linked site privacy page.

## Run focused tests

```sh
node tests/test_app.js
SOC_LOG_LAB_URL=https://randomvibez.ai/soc-log-lab/ uv run --with playwright --with pytest python3 -m pytest -q tests/test_browser_downloads.py
```

The Node tests exercise deterministic scenario-content/order generation, per-generation CSPRNG IDs, seed privacy, row and finding bounds, output labels, vendor-format caveats, Linux raw syslog line counts, missing-Web-Crypto failure behavior, and input validation. The collected Playwright tests open a fresh browser context against the public app, verify actual saved analyst/key/syslog downloads and cross-references, and check first-visit mobile layout. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` when Chromium is installed outside Playwright's default cache; set `SOC_LOG_LAB_URL` only for a deliberate alternate test target.

## Public references (research preflight)

Sources were checked through public search-result descriptions, not represented as full-text review:

- RFC 5424, Syslog message format: <https://datatracker.ietf.org/doc/html/rfc5424>
- Microsoft Sentinel Syslog table reference: <https://learn.microsoft.com/en-us/azure/azure-monitor/reference/tables/syslog>
- Microsoft Sentinel ASIM Audit schema: <https://learn.microsoft.com/en-us/azure/sentinel/normalization-schema-audit>
- CrowdStrike Parsing Standard overview and parser fields: <https://developer.crowdstrike.com/ngsiem/cps/overview/> and <https://developer.crowdstrike.com/ngsiem/cps/compliant-parsers/>
- Rapid7 generic syslog/event-source docs and Universal Event Format docs: <https://docs.rapid7.com/insightidr/insightidr-event-sources/> and <https://docs.rapid7.com/insightidr/rapid7-universal-event-sources/>

Competitive alternatives:

- Cisco Talos EvidenceForge describes deterministic multi-format generation, scenario configuration, cross-source correlation, and separate ground-truth artifacts: <https://github.com/Cisco-Talos/EvidenceForge>
- Splunk Boss of the SOC v3 is a much larger pre-indexed investigation dataset with Splunk setup requirements: <https://github.com/splunk/botsv3>
- Splunkbase Event Builder describes generated security events across many sourcetypes/domains and a companion app for Splunk delivery: <https://splunkbase.splunk.com/app/8561>

These alternatives establish that synthetic security data and ground-truth separation are not novel. SOC Log Lab differentiates only on a deliberately small, install-free, browser-local workflow with direct row/positive/difficulty controls and portable separate exports—not on demand or superiority claims.
